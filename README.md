# 研究出版系統：產品構想與使用場景

一句話定位：**把「一個觀察」展開成六個層次的思考，其中能用數據回答的部分自動幫你查證完。**

---

## 構想

### 真正的痛點不是找不到資訊

做加密貨幣內容的人每天滑兩三小時，不是因為找不到新聞——新聞到處都是。真正的問題是：**看到一則東西，腦子裡冒出「欸這背後好像有什麼」，但那個念頭沒有人陪你往下推。**

舉個實際的例子。Arc 快上線時，有人發推教大家怎麼準備玩 Arc 的 meme。這則貼文本身沒什麼好寫的，但它後面有三四層：

- 為什麼注意力集中在 meme 而不是空投？以往新鏈上線，大家都在刷空投
- 如果行為真的變了，是空投預期崩壞、meme 基建成熟，還是這條鏈本來就沒空投可期待？
- 站在項目方角度，空投跟養 meme 哪個帶來更多資金與流量？

這三層裡，第一層可以用數據量（首日成交結構），第二層要拆成互斥解釋再分別驗，第三層現在沒資料、但值得寫成觀點。

**市面上的工具停在「摘要這則貼文」。這個產品從那裡才開始。**

### 核心：六軸發散

看到任何一個觀察，系統用六個固定的軸各問一次：

| 軸 | 問什麼 |
| --- | --- |
| 行為反常 | 誰的行為跟歷史不一樣？注意力、資金、參與者組成哪一項偏離了 |
| 環境歸因 | 如果真的變了，是什麼結構改變造成的？列出**互斥**的競爭解釋 |
| 換位 | 換一個角色看，他的算盤是什麼 |
| 機制連鎖 | A 發生 → 誰被迫做 B → 誰承受 C |
| 時間結構 | 有沒有固定時點造成的週期性 |
| 反面 | 如果這說法是錯的，會看到什麼 |

軸是固定的，這很重要——**固定的軸會逼你問出自己原本不會問的那一題**。你本來只想到「注意力跑去 meme 了」，但「換位」這個軸會強迫你算一次項目方的帳。

### 每個角度標三種狀態，三種都留

- **現在可量**——資料拉得到，今天就能算 → 進查證流程
- **要等事件**——需要某個時點才有對照 → 先建基準線
- **只能推演**——沒有公開資料可驗 → **留著當觀點文素材**

第三類是這個產品跟「數據工具」最大的差別。大部分系統會把不可量的東西丟掉，但一個內容創作者真正有辨識度的文章，常常就寫在那裡。規則是：同一個推演被三個不同觀察指到，就值得單獨寫一篇。

### 可量的那部分，才啟動重機具

選中一個「現在可量」的角度之後，系統才開始做貴的事：讀一手來源、寫量測程式、跑數字。三個機制保證這部分能信：

**資訊分三層**——抓進來的、自己量過的、已被推翻的，分開存放。量過的數字必須標量測日期，鏈上參數會變。

**換一家公司的 AI 來挑錯**——只給結論、數據、方法，不給推理過程。看過推理鏈的審查者會被說服。

**每個結論押一條可驗證的預測**——三個月後看哪個數字、門檻多少、當初為什麼這樣想。到期自動判定。

### 不做的三件事

不自動發文、不給投資建議、不追求產量。第三點最違反直覺：**不選題沒有任何代價**。有產量壓力的系統會逐步降低標準。

## 使用場景

### 場景一｜看到一則教學文（發散的起點）

早上通勤，手機收到當日重點。其中一則是「有人在教怎麼準備玩 Arc 的 meme」——系統刻意把這類「有人在教別人怎麼做某件事」的貼文排在前面，因為它洩漏的是大家現在在意什麼，訊號比新聞本身強。

點開來，底下不是一句摘要，是六個角度：

```
🔬 1a 行為反常｜注意力在 meme 不在空投，跟歷史相反
💭 1b 環境歸因｜空投預期崩壞／meme 基建成熟／Arc 本來就沒空投預期
⏳ 1c 換位｜項目方角度：空投 vs 養 meme 哪個帶來更多橋入資金
🔬 1d 機制連鎖｜發射台抽成進了誰口袋，有沒有回流成鏈的收入
💭 1f 反面｜下條有空投預期的新鏈上線時，注意力應該還是在 meme
```

你掃一眼，發現 1b 那三個互斥解釋裡，第三個是你沒想到的——**如果 Arc 本來就沒有空投可期待，那「環境改變」這個大假設反而被削弱了**。系統被要求優先列出能削弱自己假設的解釋。

### 場景二｜看到機制型消息

另一則是幣安要對幾檔股票代幣發現金分紅。直覺是：以這些股票代幣為底池的 meme，分紅會不會在固定時間造成拋壓？

機制連鎖那個軸會先確認一個環節：**分紅是怎麼發的**。如果是係數調整而非現金派發，那不是資金流出，而是計價幣數量變多——方向跟拋壓相反。這個反轉比原本的假設更有意思。

時間結構那個軸會補上：記錄日有兩個，要對到哪一個時點決定了抓哪段資料。

### 場景三｜選一個角度，系統接手

點 `1a`，或直接打 `/pick 2b`。選完就結束，整件事五分鐘。

有空的時候跟系統說開工，它從佇列接手：讀一手來源、寫量測程式、跑數字、登記預測、送去給另一家公司的 AI 挑錯、逐條裁決、產出草稿。草稿開頭附「審稿前情提要」——事件時間線、哪些是一手哪些是轉述、哪些地方最該被挑戰。

審三十到六十分鐘，改成自己的語氣，自己發。

### 場景四｜推演型角度累積起來

💭 那些角度不會消失。三個禮拜後，你發現「空投預期崩壞」這個推演已經被三個不同的觀察指到過——那就不是一個角度了，那是一篇文章的主題。

### 場景五｜等事件型的角度到期

⏳ 那些角度會在事件前提醒你建基準線。除息日前後各抓 48 小時的逐筆成交，事件發生時手上已經有對照組，不用臨時補。

### 場景六｜三個月後預測到期

系統自動跑判定，印出命中或落空。落空的才是重點：對照當初的理由，找出推理哪一步沒成立。推翻了哪個知識點，就把它從「已實測」搬到「已推翻」，並記下這個坑。

## 適合誰

靠「比別人想得多一層」取勝的創作者。不是靠快、不是靠量。

有技術背景能自己驗證更好，但這不是門檻——門檻是**看到一則消息時，會不會想問「所以呢」**。這個產品做的事，是把那個「所以呢」系統化，再把其中能算的部分算給你看。

不適合想讓 AI 自動發文的人、想做交易訊號的人、一週要發五篇的人。
